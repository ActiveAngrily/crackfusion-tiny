# Crack detection and segmentation: localization literature

**Scope:** crack-specific localization, dense prediction, and segmentation models that combine convolutional/local processing with Transformer/global context. Checked 6 October 2026. This is an adjacent-task survey for the paper's image-level SDNET2018 classifier.

## Scope and task boundary

The project predicts one binary label per 224×224 SDNET2018 tile: crack or no crack. It does not predict where a crack lies, its shape, width, or severity. Segmentation papers instead learn from pixel-annotated images and output a dense crack-probability/mask map; instance segmentation may additionally separate individual crack objects, while salient-object-detection (SOD) methods output foreground saliency maps. These are useful architecture and problem-context precedents, not task-matched baselines. Do not compare their pixel Dice/IoU/F1/accuracy with image-classification recall/F1/AP/balanced accuracy.

The dominant crack morphology challenges are thin structures, faint boundaries, long-range continuity, class imbalance (crack pixels are a small fraction of image area), texture/shadow confusion, and domain shift between surfaces/cameras. CNN–Transformer methods allocate local texture/edge extraction to convolution and broader context to attention, then fuse feature maps through parallel or staged encoders and decode them back to image resolution. CrackFusion-Tiny shares the local/global motivation but is much smaller in output structure: shared stem, local convolution branch, 2-layer Transformer branch over a 14×14 grid, one concat+1×1 fusion, global pooling, one binary logit. No mask decoder or per-pixel labels are present.

## Closest analogues: what transfers and what does not

### Explicit parallel local/global fusion

DTrC-Net (2023), the 2024 pavement dual-path network, DefNet (2024), CCDFormer (2025), EfficientCrackNet (WACV 2025), CrackHCT-Net (2026), DMSRCrack (2026), PARNet (2026), and GLEF-Net (2026) make clear that separate or complementary convolutional and attention paths for crack imagery are established. Designs vary: parallel full encoders, staged CNN-to-Transformer processing, Transformer blocks interleaved with convolution, or delayed fusion. Therefore the broad claim “we combine CNN and Transformer features for cracks” is not defensible as novel.

CrackFusion-Tiny can be positioned more narrowly: a compact image-level classifier with a shared stem, one local convolution path, one global token path, and one fusion point. The segmentation architectures generally preserve spatial maps over several scales, have skip connections and a decoder, and learn from pixel-level masks. The shape of the output and annotation burden are a substantive distinction; calling this classifier a segmentation model or comparing mask metrics would be incorrect.

### Efficiency is task- and hardware-dependent

EfficientCrackNet is the best directly visible scale comparison in this set: 0.26M parameters versus the project's code-measured 0.284M. That resemblance supports a careful parameter-scale context statement only. EfficientCrackNet emits a mask and its reported FLOPs/latency include its own input size, implementation and hardware. Parameter counts alone do not establish comparable runtime, memory, or accuracy. DMSRCrack's 11.66M is a useful counterexample to assuming all dual-path segmenters are compact. For our study, compare latency/peak memory only after measuring models under a shared input, runtime, device and batch protocol.

### Labels, data provenance and evaluation

Dense segmentation needs crack/background mask annotations at pixel level; some tasks use multi-class defect labels, object instances, or saliency maps instead. SDNET2018 supplies image/tile-level binary classes for the current project; it does not supply masks for this classifier. Converting classification tiles into segmentation training data would require new mask labels or another dataset and a different experiment.

Segmentation benchmark splits are often image-level random splits. Nearby crops/tiles from the same parent photograph or capture scene can inflate apparent generalization if split independently. DMSRCrack's leave-one-dataset-out experiment is stronger evidence about dataset shift than a random within-dataset split, but dataset shift is not identical to the project's parent-photo-separated split or its held-out-surface rotations. PARNet's stated 300/237 split is recorded as reported; the accessible primary preview did not establish source grouping. Never infer source independence from a paper merely saying “train/test split.”

Metrics also answer distinct questions: pixel precision/recall/F1, Dice, IoU, mIoU, and boundary scores measure mask overlap or localization; image-level classification scores measure a tile label. Saliency-map Accuracy can be particularly dependent on vast background regions. No cross-paper ranking is meaningful without common labels, image resolution, thresholding, split, and metric definitions.
