# Crack detection and segmentation: localization literature

**Scope:** crack-specific localization, dense prediction and segmentation models that combine convolution/local processing with Transformer/global context. Checked 6 October 2026. This is an adjacent-task survey for the paper's image-level SDNET2018 classifier.

## Scope and task boundary

The project predicts one binary label per 224×224 SDNET2018 tile: crack or no crack. It does not predict crack location, shape, width or severity. Semantic segmentation instead uses pixel-annotated images to predict a dense crack/background map. Instance segmentation may separate crack objects; salient-object detection (SOD) produces a foreground saliency map. These are architecture and problem-context precedents, not task-matched baselines.

Crack segmentation targets thin structures, weak boundaries, long-range continuity, severe pixel imbalance, texture/shadow confusion and domain shift. CNN–Transformer systems commonly assign local texture and edge extraction to convolutions and broader context to attention, then fuse spatial features and decode them to image resolution. CrackFusion-Tiny shares this local/global motivation but has a different output: a shared stem, local convolution branch, two-layer Transformer branch on a 14×14 grid, one concat+1×1 fusion, global pooling and one binary logit. It has no mask decoder and uses no pixel-level labels.

## Closest analogues and what transfers

DTrC-Net (2023), the 2024 pavement dual-path model, DefNet (2024), CCDFormer (2025), EfficientCrackNet, CrackHCT-Net, DMSRCrack, PARNet and GLEF-Net show that complementary local convolution and global attention for crack imagery is an established direction. Architectures vary from parallel encoders to staged processing, interleaved blocks and late fusion. The broad claim “we combine CNN and Transformer features for cracks” is therefore not defensible as novel.

A narrower description of CrackFusion-Tiny is supported: a compact image-level classifier with shared stem, explicit local and global branches and one fusion point. Most segmentation counterparts retain multi-scale spatial features, use skip connections and decode dense maps. Their pixel-mask outputs and annotation requirements differ substantively from this project's single tile label.

EfficientCrackNet's reported 0.26M parameters is a useful scale context beside CrackFusion-Tiny's 0.284M, but parameter count alone does not compare latency, memory or accuracy. Input size, hardware, implementation and output task differ. DMSRCrack's 11.66M parameters illustrates that dual-path segmenters need not be compact. Report efficiency comparisons only from measurements under a shared input, device, runtime and batch protocol.

Segmentation requires crack/background pixel labels; some papers instead use multi-class defect labels, instances or saliency maps. SDNET2018 supplies image/tile-level binary classes for the current experiment, not masks. A segmentation experiment would require new mask labels or another dataset and a distinct protocol.

Random image-level splits may place crops or images from the same source scene on both sides. A paper's generic train/test split does not establish source independence. DMSRCrack's leave-one-dataset-out tests address dataset shift, but not the project's parent-photo-separated splits or held-out-surface rotations. Pixel precision/recall/F1, Dice, IoU, mIoU and boundary scores measure dense localization; image-level classifier recall/F1/AP/balanced accuracy measure tile labels. Do not compare these metrics across tasks or treat accuracy as equivalent evidence without matching labels, split and metric definition.
