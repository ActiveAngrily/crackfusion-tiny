# MobileViT Baseline and CrackFusion-Tiny Transition Plan

**Prepared:** 2026-09-01  
**Immediate goal:** produce a working, clearly labelled MobileViT crack-classification baseline for the presentation tomorrow.  
**Research goal:** use that baseline to understand MobileViT before implementing the explicit local/global fusion model specified in Phase 3.

## 1. Decision

Use the pretrained **MobileViT-XS** checkpoint hosted on Hugging Face through `timm`:

```python
model = timm.create_model(
    "mobilevit_xs.cvnets_in1k",
    pretrained=True,
    num_classes=1,
)
```

Why this is the default:

- It is the 2.3M-parameter MobileViT-XS described in the project literature and fits the Phase 3 target range of roughly 1-3M parameters.
- The checkpoint is pretrained on ImageNet-1K and only the classifier must be replaced for binary crack classification.
- `timm` exposes the model-specific preprocessing and intermediate feature maps, which will help us inspect MobileViT now and modify the design later.
- It avoids adopting Apple's full CVNets training framework for a one-model experiment.

Use `mobilevit_xxs.cvnets_in1k` (1.3M parameters) only if XS is too slow or memory-limited. The native Transformers checkpoint, `apple/mobilevit-x-small`, is the fallback if the `timm` route fails. Do not implement MobileViT from scratch for the baseline.

Terminology for the presentation: call the model **MobileViT** or **MobileViT-XS**, not simply “MViT.” MViT is also commonly used for the separate Multiscale Vision Transformer family.

## 2. What the existing research fixes for us

The local [Phase 2 synthesis](phase2_synthesis.md) and [Phase 3 methodology](phase3_crackfusion_methodology.pdf) already establish these constraints:

- Task: binary crack/no-crack image classification, not segmentation or crack-width estimation.
- Main dataset: SDNET2018, with 56,092 tiles derived from only 230 photographs across deck, wall, and pavement surfaces.
- Main validity risk: tiles from the same parent photograph must not cross research train/validation/test splits.
- Imbalance: 8,484 crack tiles versus 47,608 non-crack tiles, so accuracy alone is insufficient.
- Primary metrics: crack recall, F1, PR-AUC, and balanced accuracy; also report precision, ROC-AUC, and a confusion matrix.
- Architectural lesson: convolution should preserve local crack texture, while attention should operate after spatial reduction.
- MobileViT is the reference for forming tokens from CNN feature maps, applying global processing, folding them back into a feature map, and fusing local/global information.

The shared Zotero group confirms the key sources:

- `UZT7VV56` — Mehta and Rastegari, *MobileViT*, 2022.
- `UBGE2XUB` — Dorafshan et al., *SDNET2018*, 2018.
- `KU57S9P4` — Russel and Selvaraj, *MultiScaleCrackNet*, 2024.
- `B9X3LZ38` — Yadav et al., concrete-crack CNN/Transformer hybrid, 2024.

## 4. Track A — presentation-ready baseline

This track proves the pipeline. It is not the final Phase 3 experiment.

### A1. Create the smallest environment

Use one Python environment with only:

- PyTorch and torchvision;
- `timm`;
- scikit-learn for metrics;
- matplotlib only if plots are generated by the training script.

The current machine is an M4 MacBook Air with 16 GB memory, so start with PyTorch MPS and batch size 16 or 32. If a short benchmark shows that a full run will miss the presentation deadline, move the same script to a Colab GPU. Do not build separate local and Colab codepaths.

### A2. Smoke-test the exact checkpoint

Before touching the dataset:

1. Load `mobilevit_xs.cvnets_in1k` with pretrained weights and one output logit.
2. Resolve preprocessing from the model with `timm.data.resolve_model_data_config`; do not manually guess RGB/BGR order, normalization, crop size, or interpolation.
3. Run one batch shaped `[2, 3, 256, 256]`.
4. Require output shape `[2, 1]`, no NaNs, and a parameter count close to 2.3M.
5. Print intermediate feature-map shapes using `features_only=True` for a presentation diagram.

Exit criterion: one deterministic forward pass and one saved architecture/shape summary.

### A3. Obtain and inventory SDNET2018

Download the official CC BY 4.0 archive from [Utah State University](https://digitalcommons.usu.edu/all_datasets/48/) rather than an undocumented mirror. The official record provides the DOI, archive, readme, class description, and checksum.

Create one CSV manifest with:

```text
path,label,surface,parent_id,split
```

For the presentation run, inspect folder names and filenames, count every class/surface, reject unreadable images, and record whether `parent_id` can be recovered. Do not silently invent parent IDs.

### A4. Make a time-boxed development split

Preferred: use a parent-grouped development split immediately if parent IDs are recoverable.

Fallback for tomorrow only: create a fixed, balanced, surface-stratified subset such as 2,000 crack and 2,000 non-crack tiles, with a deterministic 80/20 train/validation tile split. Label every result:

> Preliminary pipeline validation only; tile-level splitting may contain parent-photograph leakage and is not a Phase 3 result.

Do not call this test accuracy and do not compare it with published scores.

### A5. Fine-tune MobileViT-XS

Use one logit with weighted `BCEWithLogitsLoss`; compute `pos_weight = N_negative / N_positive` from the training partition only.

Presentation schedule:

1. Freeze the pretrained backbone and train the new classifier for 3 epochs at learning rate `1e-3`.
2. Unfreeze the complete model and fine-tune for 5-10 more epochs at `1e-4` with AdamW.
3. Retain the checkpoint with the best validation F1.
4. Use the Phase 3 crack-safe augmentations: flips, rotation within ±15°, mild brightness/contrast jitter, and crop scale no lower than 0.85.

This is intentionally shorter than the final training protocol. Its purpose is to show that the pretrained MobileViT learns the crack task and that the data, loss, checkpoint, and evaluation paths work.

### A6. Produce four presentation artifacts

Generate only:

1. a MobileViT tensor-flow/feature-shape diagram;
2. training and validation loss/F1 curves;
3. a validation confusion matrix with crack recall and F1;
4. a small panel of correct predictions, false positives, and false negatives.

If the run is development-only, place the limitation directly below the metric table on the slide.

## 5. Track B — research-valid MobileViT baseline

Begin this after the presentation pipeline is stable.

### B1. Lock data provenance

1. Hash every image and remove exact duplicates before splitting.
2. Recover or conservatively reconstruct all 230 parent-photograph groups.
3. Freeze a parent-grouped 70/15/15 train/validation/test manifest.
4. Keep surface type in the manifest for deck/wall/pavement reporting.
5. If parent IDs cannot be recovered, do not claim a source-separated pooled result; prioritise leave-one-surface-out evaluation and document the limitation.

### B2. Train the reference baseline

- Model: pretrained `mobilevit_xs.cvnets_in1k`.
- Input: its official 256×256 preprocessing. This is a transfer-learning reference, not a parameter-matched Phase 3 model.
- Loss: weighted BCE, without simultaneously using a balanced sampler.
- Optimizer: AdamW.
- Schedule: frozen head warm-up, then up to 30-50 fine-tuning epochs with cosine decay and validation-F1 early stopping.
- Seeds: 42, 1337, and 2026.
- Selection: validation data only; keep the final test sealed.

Report mean and standard deviation across seeds for crack recall, F1, PR-AUC, balanced accuracy, precision, ROC-AUC, parameters, model size, and measured latency.

### B3. Run cross-surface tests

Run three rotations:

- train on wall+pavement, test on deck;
- train on deck+pavement, test on wall;
- train on deck+wall, test on pavement.

No threshold or hyperparameter may be selected using the held-out surface.

Exit criterion: MobileViT-XS has a reproducible source-aware baseline table and saved per-image predictions.

## 6. Learn MobileViT before modifying it

Use the trained baseline to document this flow:

```text
image
  -> MobileNetV2-style convolutional stages
  -> local convolution in a MobileViT block
  -> feature-map patches
  -> Transformer processing across patches
  -> fold back to a spatial feature map
  -> concatenate/fuse with local features
  -> convolutional stages and classifier
```

For one batch, save the input/output shape at every MobileViT block and calculate parameters per stage. This is enough to explain the model in the presentation and to choose the later CrackFusion fork point. Do not rewrite attention just to demonstrate it.

## 7. Transition from MobileViT to CrackFusion-Tiny

The Phase 3 architecture is inspired by MobileViT but is not merely a new classifier head. It changes the feature flow into explicit, independently ablatable local and global branches.

Implement it only after the baseline is stable:

1. **Shared stem:** 224×224 input to a 28×28×64 convolutional feature map.
2. **Local branch:** two depthwise-residual blocks to 28×28×96, then pool to 14×14×96.
3. **Global branch:** overlapping stride-2 convolution to 14×14×96; form 196 feature tokens and process them with one or two compact Transformer encoders/MobileViT-style global blocks.
4. **Fold/alignment:** return global tokens to a 14×14×96 map.
5. **Explicit fusion:** concatenate local/global maps once, apply a 1×1 convolution to 128 channels, global-average-pool, and emit one logit.

Start with fixed concat+1×1 fusion. Add a learned gate only as an ablation after the fixed model works.

The minimum comparison is:

| ID | Model | Purpose |
|---|---|---|
| R0 | Pretrained MobileViT-XS | Practical reference and starting point |
| B1 | Matched CNN-only branch | Tests whether local features are sufficient |
| B2 | Matched Transformer-only branch | Tests whether global tokens are sufficient |
| B3 | Serial stem→Transformer hybrid | Tests whether serial composition explains any gain |
| H1 | CrackFusion-Tiny | Tests explicit local/global fusion |

Only after H1 works should we run Transformer-depth, token-grid, and fusion-type ablations.

## 10. Presentation narrative

1. **Why MobileViT:** convolution captures thin local cracks; Transformer blocks connect distant crack segments and surrounding context.
2. **What we reused:** a public ImageNet-pretrained 2.3M-parameter MobileViT-XS model rather than reimplementing the architecture.
3. **What we built:** a binary crack-classification pipeline with reproducible preprocessing, imbalance-aware loss, metrics, and error examples.
4. **What is preliminary:** any tile-random development result is a pipeline check, not research evidence.
5. **What comes next:** expose local/global branches, fuse once, and compare CrackFusion-Tiny against matched CNN, Transformer, and serial MobileViT-style baselines under parent-separated and held-out-surface evaluation.
